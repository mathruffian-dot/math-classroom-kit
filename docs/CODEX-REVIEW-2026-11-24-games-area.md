# Codex 審核：遊戲區、遊戲區開魔王戰、十字交乘對戰頁（2026-11-24）

審核者：Codex CLI（gpt-6.2-astra，model_reasoning_effort=high，read-only）。任務：`docs/codex-review-games-area-task.txt`。

**需修正後再審。** 從遊戲區開魔王戰可能結束老師未確認的課堂，而且目前按「開始魔王戰」只會進入設定頁，全班尚未開戰。

## 阻擋

1. **確認的是 A 堂，實際可能結束 B 堂。** 位置：`src/main.ts:3099`、`src/main.ts:3107`、`worker/app.ts:1481`。前端查詢目前課堂後，確認按鈕只保留班級與目標教材 ID。若另一分頁在老師確認前已把 A 堂換成 B 堂，伺服器會直接結束 B 堂。原先查到「沒有進行中的課」也有相同競態。**修正方向：**讓開戰請求帶上老師看到的課堂 ID，無課時明確傳 `null`。在同一個 Durable Object 操作裡比對、沿用或取代課堂；狀態已變就回 `409`，顯示最新課堂供老師確認。補雙分頁測試，斷言 B 堂仍在進行，且另一班不受影響。

2. **「選單元＋選班級就開戰」尚未完成。** 位置：`docs/REVIEW-2026-11-24-games-area.md:8`、`src/main.ts:3791`、`src/main.ts:3401`、`tests/e2e/games.spec.ts:53`。`startRaidGame()` 建立或沿用課堂、翻到 `raidPage` 就返回；只有在課堂面板再按一次才會送 `raid-start`。現有測試驗到面板和「魔王戰」頁名就結束，因此即使沒有場次、學生不能出招也會通過。**修正方向：**在遊戲卡選好設定或採用預設值，一次完成開課、定位與開戰；同一場已在進行時直接進入。測試應斷言 `session.raid.id` 已建立、獨立學生端進入戰鬥流程，再按入口時同一場的進度仍在。

## 應修

1. **即使老師同意換課，舊課也跳過正常結算。** 位置：`worker/app.ts:1481`、`worker/app.ts:1989`、`worker/app.ts:435`。開新課只設定 `ended` 等欄位；一般「結束課堂」還會結算測驗、十字交乘與步驟格鬥。例如舊課正進行不限時十字交乘拔河，換課後課堂已結束，該場卻可能沒有結束時間與勝負紀錄。**修正方向：**兩個入口共用結課邏輯，並測試被取代課堂的場次紀錄與班級測驗統計。現有 `games.spec.ts:55` 只檢查 `session.ended`。

2. **沿用同一堂課會無條件翻頁並清除活動狀態。** 位置：`src/main.ts:3793`、`worker/app.ts:1561`。就算已在魔王戰頁，仍送出 `slide`，清掉搶答、得主、作答期限、補救練習及結果顯示。若同班正在同一教材的另一頁限時作答，老師進入遊戲設定時，全班作答就先被關閉。另有一種情況是課堂快照沒有後來才新增的魔王戰頁，`findIndex()` 回 `-1` 後仍導向課堂。**修正方向：**先驗證實際課堂快照，已在目標頁就略過翻頁；會中止既有活動時，在老師確認開戰後一併處理。補「同頁保留搶答」與「舊快照缺頁」測試。

3. **遊戲卡可能指向沒有題庫的課程，甚至先結束原課才發現不能玩。** 位置：`src/main.ts:234`、`src/main.ts:239`、`worker/raid.ts:30`、`worker/app.ts:1640`。前端憑課程 ID 格式與 `raidPage` 列卡，後端則依 `raidBank(lessonId)` 決定能否開戰。匯入一份 ID 符合格式、保留 `raidPage` 的課程副本，就可能顯示不可玩的卡；同單元有兩個候選時，後掃到的還會覆蓋原本可玩的課程。**修正方向：**由後端提供可開戰的單元及教材 ID，只傳名稱與識別資料；在變更任何課堂前驗證題庫與頁面都存在。

4. **教師手選的十字交乘重點會在整頁重畫時消失。** 位置：`src/main.ts:1626`、`src/cross-live.ts:209`、`src/main.ts:1696`、`src/main.ts:3806`。例如頁面預設 `gcf`，老師改選 `a1`，再按「搶答」；控制指令成功後會重建教師面板，又選回 `gcf`。`crossPanelKey` 能避免部分更新重畫，但整個 `renderSession()` 會直接替換 DOM。**修正方向：**以課堂 ID＋投影片 ID 保存尚未開戰的表單選擇，首次進頁才套頁面預設。補測改選、同頁重畫、開戰，並確認學生收到手選重點的題目。

5. **`crossPage.focus` 的執行期驗證比資料契約寬鬆。** 位置：`worker/validation.ts:469`、`shared/game-focus.ts:55`、`tests/e2e/games.spec.ts:79`。我用目前的 `validateLesson()` 在記憶體實測：`"hard"` 回 `400`，但 `["gcf"]` 會被 `String()` 轉成 `"gcf"` 並接受。**修正方向：**把原值直接交給既有的 `isCrossFocus()`，並以單元測試覆蓋四個有效字串及陣列、缺值、未知字串。

## 建議

1. **讓學生在開戰前看到明確的等待狀態。** 位置：`src/main.ts:1194`、`tests/e2e/games.spec.ts:75`、`tests/e2e/games.spec.ts:97`。教材區有玩法，但沒有一般活動時，作答區仍顯示「這一頁沒有題目，跟著老師操作圖形」。此外，測試用的對戰頁本來就沒有 `activity`，所以 `.teacher-activity` 數量為零也無法證明一般活動區已隱藏。建議學生端顯示「等待老師開始十字交乘對戰」，並分別驗證學生等待文字、教師無一般活動提示，以及開戰後作答卡取代教材。

2. **補遊戲區本身的窄螢幕與鍵盤驗收。** 位置：`src/cross.css:520`、`src/main.ts:252`、`tests/e2e/games.spec.ts:16`。新版教師遊戲區只用 1440px 寬測試；卡片欄寬下限是 320px，多張卡的選單與按鈕也都叫「班級」「開始魔王戰」。建議用 iPad 直橫向及窄手機量卡片溢出與觸控框，讓控制項的可及名稱帶單元名稱，並驗證用鍵盤取消換課後原課仍在。

3. **隔離測試資料，補上教材契約文件。** 位置：`tests/e2e/games.spec.ts:9`、`tests/e2e/games.spec.ts:25`、`tests/e2e/games.spec.ts:78`、`docs/AUTHORING.md:35`。測試修改 `DEMO801.requireCode`、寫入固定 ID 教材，結束時只刪課堂；重用本機測試站會留下設定與教材。建議使用測試專屬班級和唯一教材 ID，並在作者指南補 `crossPage` 範例、四種重點及開戰前後的畫面行為。

## 已確認沒問題的項目

- **答案與題庫。** 就本批新增路徑，未發現把魔王題庫、十字交乘場次種子或當題正解送到學生端。`crossPage` 只保留重點，投影片上的因式分解是固定教學示例。學生 HTTP 與 WebSocket 共用過濾後的 `sessionView()`，十字交乘發題另以 `itemView()` 明列可公開欄位。位置：`worker/app.ts:729`、`worker/app.ts:1050`、`worker/cross.ts:285`、`worker/raid.ts:251`。
- **十字交乘的正常師生流程。** 首次進入對戰頁會開啟面板並套用頁面重點；開戰後學生端會切換作答卡並自動取題。新增測試確實使用獨立學生 browser context，檢查從 `gcf` 等待頁進入 level 3 題目。位置：`src/main.ts:1222`、`src/main.ts:1670`、`src/cross-live.css:646`、`tests/e2e/games.spec.ts:91`。
- **基本操作與驗證範圍。** 班級使用原生 `select`，確認視窗有標題、初始焦點、Tab 循環及 Escape 關閉。按鈕與選單的基礎最小高度為 46px，重點選項為 56px。這次唯讀審查實際跑過 `tsc --noEmit --incremental false` 與上述驗證器案例。交接檔記載的 `196/196`、`games.spec` 的 `2/2` 是前次結果；本次未重跑會寫入產物的完整測試，也未驗證正式站或 iPad Safari 實機。
