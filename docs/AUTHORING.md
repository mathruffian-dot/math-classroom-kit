# 教材格式與認知科學設計

教材是 `content/lessons/*.json`（`schemaVersion: 1`）。最終驗證依據是 `worker/validation.ts`，執行 `npm run lessons` 即可檢查。

## 一、認知科學設計流程

每份課程依下列順序排頁。每頁的 `phase` 填寫該頁的階段名稱：

| 階段（phase） | 目的 | 常用 IRS |
| --- | --- | --- |
| 提取練習 | 先喚起需要的舊知識（retrieval practice） | `numeric` 多小題 |
| 預測 | 講解前先猜，讓迷思浮現（pretesting） | `single`，先公布統計、暫不公布答案 |
| 具體操作 | 拖拉、切割、移動圖形（CRA 的具體階段） | `manipulate` |
| 圖式連結 | 圖和式用同色對應；逐步揭示，目前步驟發光 | `numeric`／`single` |
| 工作範例 | 先讓學生試算，再逐步講解 | `numeric`（就是例題本身） |
| 半完成範例 | 只留關鍵步驟讓學生完成（fading） | `numeric` |
| 隨堂練習 | 課本隨堂，加上換數字的同類題，共 1–3 小題 | `numeric` + `items` |
| 錯誤分析 | 找錯、更正並說明理由（自我解釋） | `canvas` + `rubric` |
| 交錯練習 | 混合不同類型的題目 | `multiple` |
| 出場券／後設認知 | 用自己的話說明、自評 | `short` + `rubric`、`scale` |

**檢查表**（`npm run lessons` 會自動提醒）：

- 每頁一個重點，內文 90 字以內。
- 每頁都有 IRS。
- 有步驟揭示的頁面，要設定 `step`／`focus`，讓目前步驟發光。
- **例題、隨堂、錯誤分析：依課本的解法，把解題過程步驟化或結構化地呈現**（逐行等號鏈、左右兩欄、面積模型、數線），不一定要做滑桿。滑桿留給「操作本身就是重點」的頁面（具體操作、概念探索）。
  - 隨堂頁的示範用**另一組數字**，不要示範 IRS 的原題。
  - 錯誤分析頁只給結構、結果留「？」，不要直接給正解。
  - 樣板在 `scripts/lessons-src/viz.mjs`：`stepsViz`（等號鏈）、`multSteps`（係數欄／根號欄）、`compareSteps`（比大小）、`binomialSteps`（和的平方面積模型）。最後一步會把全部步驟點亮。
  - 單欄等號鏈會由 `tests/content.test.mjs` 自動驗算。
- `canvas`、`short` 題要附評量規準（rubric），並寫好參考解答。
- 每頁標示 `source`（課本頁碼）；自編題目也要註明是自編。

## 二、頁面（slide）欄位

```json
{
  "id": "a-ex1",
  "phase": "工作範例",
  "eyebrow": "04 / 例 1 根式的乘法",
  "title": "√a × √b ＝ √(a×b)",
  "body": "長 √a、寬 √b 的長方形，面積是 √(ab)。",
  "source": "對應課本 2-2 p.74",
  "notes": "教師備註，學生看不到",
  "figures": [{ "src": "g8-2-2/ex1.png", "alt": "課本 p.74 例 1 題目" }],
  "interactive": { "...": "見第三節" },
  "activity": { "...": "見第四節" }
}
```

**數學式寫法**

- 用 `$…$` 包住 LaTeX，例如 `$\frac{4\sqrt{5}}{15}$`。
- 純文字也會自動排版成課本樣式：`√3 × (−2√5)`、`4/(3√5)`、`(√5+√3)/2`、`(a+b)²`。
- 自動排版會保留原本寫的括號、×、÷。若要精準控制（例如分數係數），請寫 LaTeX。
- 在 JS 產生器裡寫 LaTeX 時用 ``String.raw`…` ``，避免反斜線被轉義。

**課本截圖**

- `figures` 最多 3 張，路徑格式是「課程資料夾/檔名.png」，檔案放在 `public/lesson-assets/`。
- 截圖會排成一列顯示在頁面上方。授課中點一下，會在投影片區內放大：畫筆、橡皮擦、雷射、聚光、翻頁、IRS 都照常可用；放大時的筆跡另存，縮小後不會蓋到原版面（Esc 或「縮小」）。
- 只截最重要的區塊（題目框與附圖），不要截整頁。
- 只有已登入的師生看得到截圖，而且截圖不進 git。

**整頁簡報圖（fullSlide）**

- 把現成簡報整份放進來（例如非數學的彈性課程）：每頁一張簡報圖，`"fullSlide": true`，`figures` 剛好 1 張。
- 圖填滿投影片區、不加「課本」標籤；`title` 只用在頁碼點與教師畫面，不另外顯示（簡報圖本身有標題）。點圖一樣可以放大標註。
- 範例：`scripts/lessons-src/gender-joke.py`（PDF 每頁轉 JPG，講稿放 `notes`）。

**動畫片段（animation）**

```json
"animation": { "src": "g8-2-2/anim-a-ex1.mp4", "poster": "g8-2-2/anim-a-ex1.png", "caption": "為什麼 √2 × √3 ＝ √(2×3)", "seconds": 27.3 }
```

- 靜音 mp4＋封面圖，檔名以 `anim-` 開頭，放在 `public/lesson-assets/`（和截圖一樣不進 git，部署時上傳）。
- 每頁一段，和課本截圖排在同一列；點一下在投影片區內播放，暫停後可以直接用畫筆標註。
- 頁面有 IRS 時，學生端要等老師在這一頁按「公布結果」才解鎖（伺服器端鎖定，直接讀檔也會被擋）；`"reveal": "always"` 則一律可看。預測頁若要「保留疑問到下一頁」，就不要放動畫。
- 2-2 的動畫由 `八年級/影片/根式的運算_動畫簡報_v1/tools/export_classroom.py` 從解說影片剪出，對照表在 `scripts/lessons-src/g8-2-2-animations.json`。

## 三、可操作視覺化（interactive）

**座標**：使用數學座標（y 向上）。幾何圖形請加上 `aspect: "equal"`。

```json
{
  "view": { "xMin": -1, "xMax": 12, "yMin": -1, "yMax": 12, "grid": 1, "axes": false, "aspect": "equal" },
  "params": [
    { "id": "a", "label": "$a$", "min": 1, "max": 8, "step": 1, "value": 5 },
    { "id": "cut", "label": "切割線", "kind": "toggle", "value": 0 }
  ],
  "points": [{ "id": "P", "x": 2, "y": 3, "snap": 1, "label": "P" }],
  "shapes": [
    { "type": "rect", "x": 0, "y": 0, "w": "a", "h": "a", "fill": "rgba(123,97,255,.25)", "color": "#7b61ff", "toggle": "cut" },
    { "type": "text", "x": "a/2", "y": "a/2", "text": "$a^2={a^2}$", "show": "cut" },
    { "type": "brace", "points": [[0, "a"], ["a", "a"]], "text": "$\\sqrt{a*2}$" },
    { "type": "segment", "points": [[0, 0], ["Px", "Py"]], "step": 1 },
    { "type": "function", "expr": "a*x+1" }
  ],
  "readouts": [{ "label": "面積 $a^2$", "expr": "a^2", "digits": 2 }],
  "steps": ["第 0 步說明", "第 1 步說明"],
  "caption": "圖說"
}
```

**圖形類型（type）**

| type | 用途 |
| --- | --- |
| `function` | 函數圖形，`expr` 是 y 關於 x 的式子 |
| `segment` | 線段 |
| `line` | 直線 |
| `polygon` | 多邊形 |
| `circle` | 圓 |
| `rect` | 長方形 |
| `text` | 文字 |
| `point` | 點 |
| `angle` | 角（三個點，中間是頂點） |
| `brace` | 尺寸標示線，畫在 p1→p2 方向的左側（外側） |

**運算式**

- 可用：`+ - * / ^`、比較運算、`&& || !`、`? :`。
- 函數：`sqrt abs round min max floor ceil sin cos tan`（角度制）、`gcd mod`。
- 點 P 的座標變數是 `Px`、`Py`。
- 步驟揭示的變數是 `step`，從 0 開始。

**文字樣板**

- `{運算式}` 會代入即時數值。
- 在 `$…$` 裡也可以用，例如 `$\sqrt{a*b}$` 會變成 `√21`。
- 不能解析的大括號（例如 `\text{…}`）會原樣保留。

**步驟聚焦**

- 有 `steps` 時，目前步驟相關的圖形發光，其他圖形反暗。
- 圖形預設在自己出現的那一步（`step`）發光。
- 要在其他步驟也發光，加上 `"focus": [0, 4]`。

**其他屬性**

| 屬性 | 作用 |
| --- | --- |
| `show` | 條件為假時隱藏圖形 |
| `toggle` | 點擊圖形可切換某個開關參數 |
| `step` | 第幾步之後才出現 |

**重複使用的樣板**：見 `scripts/lessons-src/viz.mjs`，包括：

- 根式長度積木
- 長方形面積乘法
- 數線比較大小
- 正方形切割化簡
- 對角線上數線
- 分母有理化
- 同類方根積木
- 分配律面積
- 和的平方
- 平方差
- 逐步解題

## 四、IRS 題型（activity）

| type | 必要欄位 | 說明 |
| --- | --- | --- |
| `single`／`multiple` | `options`（可加 `correct`） | 選擇題 |
| `scale` | `min`、`max` | 自評量尺 |
| `numeric` | `answer`，或 `items`（1–3 題） | 答案可寫分數或根式。加上 `form: "simplest-radical"` 時，數值對但沒化簡會判錯，並提示「還沒化成最簡根式」 |
| `manipulate` | `check`（例如 `"a==6 && b==2"`），可加 `record` | 學生操作同一頁的圖後送出，伺服器依 `check` 判定對錯 |
| `canvas` | `rubric`（必填），可加 `canvas: "grid"／"axes"／"dots"／"blank"`、`allowPhoto` | 手寫、作圖或拍照作答 |
| `short` | 可加 `rubric` | 短答 |
| `make` | `cards`（2–6 張，例如 `"√2"`、`"3"`）、`target`（例如 `"6"`、`"5+2√6"`） | 根式湊數挑戰：每張卡用一次，加上 ＋ − × ÷ 和括號湊出目標數。學生點卡片組算式，即時看到目前的值；伺服器判定（`shared/make.ts`），公布後列出全班的湊法 |

**全班目標條**：有對錯的題目（有正解的選擇題、數值題、操作題、湊數挑戰）開放作答後，大螢幕右上角顯示全班答對率（分母＝上線人數與已作答人數取大）。到 80% 就顯示「全班達標」並放彩帶，學生在公布結果後也看得到。

**暖身例行活動**：每堂課第一頁（`content/warmups/<課程 id>.json`，由 `scripts/lessons-src/warmups.mjs` 產生，`npm run lessons` 插在最前面）。兩種輪流出現：

- 「哪一個不一樣？」：`single` 題不設正解，加上 `visual: "cards"`。四張卡片每一張都要有一個理由，理由寫在 `explanation` 與教師備註。
- 「估一估」：`numeric` 題加 `tolerance`，用 `steps` 提示估算步驟。產生器會核對哪些答案在容許範圍內。

暖身只能用這一堂以前教過的內容。第一頁同時是老師派「間隔複習」的地方。

**根式湊數挑戰的題目**：放在 `content/make/<課程 id>.json`，由 `scripts/lessons-src/make-puzzles.mjs` 產生，插在課後檢核頁前面。產生器會窮舉所有湊法，確定每一關都有解，並把不同的湊法寫進教師備註。寫在解析裡的湊法也會核算。

**評量規準（rubric）**

```json
{
  "criteria": [
    {
      "id": "find",
      "label": "找出錯誤",
      "points": 2,
      "levels": [
        { "score": 0, "description": "未指出錯誤" },
        { "score": 1, "description": "只說錯了" },
        { "score": 2, "description": "明確指出漏了 2ab" }
      ]
    }
  ],
  "reference": "參考解答（公布前不會給學生）",
  "graderNotes": "可接受的替代做法"
}
```

**批改分兩層**

- **第 1 層（預設）**：只判斷對錯，快又省。
- **第 2 層**：教師開啟「依規準給分＋紅筆批註」後，AI 依規準逐項給分，並在學生作答圖上用紅筆批註（向量疊圖，原圖不更動）。

兩層的結果都要經教師覆核後再發回學生。

**作答限時與補救練習（numeric）**

- 老師開放作答時選限時（預設 1 分鐘，可選 30 秒～5 分鐘或不限時）。時間到就鎖住作答，老師可以「＋30 秒／＋1 分鐘」或結束作答。
- 全班作答後，老師按「派補救練習給答錯的同學」（可勾選也派給未作答的同學），派的是每個人自己答錯的那幾小題課本原題，每題再做一次（2026-10-21 起；伺服器的 `retry` 模式）。全部答對就過關，還有錯的標「需個別指導」。
- 不另外寫換數字的補救題庫。舊的 `content/practice/<課程 id>.json`（每題 3 輪換數字）格式 `npm run lessons` 仍會讀，但新課程不用。

**會考式手寫題（拍照批改，0–3 分）**

- 需要看計算過程的題目做成 `canvas` 題，評量規準用單一向度 `kai`（會考評分，滿分 3）：3 完整正確／2 觀念正確但有小錯或不完整／1 部分正確／0 空白或錯誤，每一級寫成這一題的具體描述；`reference` 寫完整解法，`graderNotes` 寫可接受的其他做法與常見錯誤。
- 放在 `content/written/<課程 id>.json`，`npm run lessons` 會插入新頁並換掉規準：

```json
{ "slides": [{ "after": "<插在哪一頁之後>", "slide": { "id": "a-written", "phase": "會考練習", "activity": { "type": "canvas", "rubric": { "criteria": [{ "id": "kai", "points": 3, "levels": [] }] } } } }],
  "rubrics": { "<既有 canvas 題 ID>": { "criteria": [{ "id": "kai", "points": 3, "levels": [] }] } } }
```

- 課堂流程：學生紙本作答 → 拍照 → AI 逐行辨識 → 學生核對 → 送出 → 自動快速批改（只看辨識稿）→ 在辨識稿上圈出錯處、寫原因 → 老師覆核後發回。

## 五、交給 agent 的提示詞

```text
請依 math-classroom-kit/AGENTS.md 與 docs/AUTHORING.md，把〈年級 單元〉做成數感課堂課程：
先盤點課本每個例題與隨堂（頁碼、題目、教用版答案），截取重點課本圖到 public/lesson-assets/，
依認知科學流程排頁，每頁都有對應的 IRS，隨堂改成 numeric items（課本題＋換數字題，最多 3 題），
錯誤分析用 canvas＋評量規準。完成後執行 npm run lessons 與 npm run check，並回報頁數與提醒。
```

## 課後形成性評量題庫（PK 戰共用）

- 每堂課一份：`content/quizzes/<課程 id>.json`，由 `scripts/quiz-src/<課程 id>.py` 產生（範例：`g8-2-2a.py`）。
- 10 個題位，每個題位 3 題「同類型換數字」的四選一題目；第 1 個選項是正確答案（派題時伺服器會打亂選項順序）。
- **範圍不能超過這一堂**：只能用這一堂與同一節前面幾堂（以及先備單元）教過的內容。例如 2-2(3) 可以用 2-2(1)～(3)，不能用 2-2(4) 的乘法公式；2-2(1) 的題目不能要求化成最簡根式或分母有理化。正確答案、解題過程都要在範圍內；錯誤選項也避免出現還沒教的寫法。產生器開頭寫明這一堂的範圍。
- 錯誤選項寫學生常見的錯法（加進根號、係數相加、正負號、乘除顛倒…），老師看選項分布就知道卡在哪裡。
- 產生器用 SymPy 核算：正確選項必須等於題目的值、錯誤選項都不能相等；「哪一個正確」的題目必須剛好一個敘述為真。
- `npm run lessons` 會把題庫併進課程（`lesson.quiz`，學生端看不到）。派題時每個題位抽 1 題，全班同一份；重新派題或 PK 會重新抽。
- **幾何題要附圖**（`figure`：SVG 文字）。用 `scripts/quiz-src/geom.py` 畫，數字一定要和題目同一組（比例照實際數字；人比大樓矮太多時可以把人的三角形等比例放大，仍然相似）。課本樣式：斜體點名、淺色填色、直角記號、等長記號，題目要求的那一段標「?」。範例：`g9-1-4a.py`～`g9-1-4c.py`，兩個相似三角形的圖在 `similar.py`。
- 附圖只能是單純的 SVG（不能有 script、事件屬性、javascript: 連結），學生端以圖片顯示。老師結束全班測驗後，在大螢幕點題目可以展開題目、附圖、選項人數與解析。
- 出完題用 `node scripts/quiz-src/preview.mjs <課程 id> <輸出資料夾>` 產生預覽圖（每張 9 題，含附圖、選項、解析），每張都要看過：圖和題目的數字一致、標籤沒有重疊或被切掉。
- 上課時的四個加強功能（程式在 `worker/quiz.ts`、`worker/app.ts`、`shared/quiz.ts`）：
  - 信心下注（全班測驗）：每題選完答案，再選「有把握」或「不太確定」才會跳下一題。計分：有把握答對 +3、答錯 −2；不太確定答對 +1、答錯 0。結束後學生看到分數，以及兩種把握各答對幾題，並附一句校準回饋（`betSummary`）；老師的大螢幕顯示全班平均。
  - 進步分數：全班測驗的成績記在班級資料（`quizHistory`，每人最近 20 次）。結束後學生看到和上一次全班測驗比，答對率差幾個百分點；老師的個別成績顯示 ↑／↓。
  - 同程度配對（PK）：依這一堂最近一次全班測驗或 PK 的答對率排序，相鄰兩人一組。這一堂還沒做過，就看之前的全班測驗；都沒有當 50%。單數時，程度最低的那位和電腦對戰。
  - 間隔複習：每一課各題位全班累計答錯幾次，記在 `quizMisses`。下一課在第一頁派「間隔複習」，題目是上一課錯最多的 3 個題型，每題換數字，作答後馬上看到對錯與解析，約 3 分鐘。題目從上一課的題庫複製進這一次（`run.bank`，只在伺服器）；成績不算進這一課的錯題紀錄。

## 魔王戰（一節的總複習，放在這一節最後一堂的最後一頁）

- 題庫：`content/raids/<這一節最後一堂的課程 id>.json`，由 `scripts/quiz-src/<節>-raid.py` 產生（範例：`g8-2-2-raid.py` → `g8-2-2d.json`）。`npm run lessons` 會在那一堂最後加一頁「魔王戰」，題庫另外存成 `content/raids.generated.json`，只在伺服器，學生端拿不到答案。
- 三類題目（學生每一題自己選）：
  - `attack`（記憶）：普通攻擊，一步就能算完的基本運算。
  - `shield`（理解）：防護罩，答對一題存 1 秒（存量不倒數，上限 30 秒）。魔王攻擊時自動扣存量擋下；沒人存很容易輸。題型是判斷相等、比大小、同類方根、估算、找出正確算法。
  - `ultimate`（應用）：大招計量，多步驟、綜合題與生活應用。
- 每類至少 10 題，建議 60 題以上：一場 5–10 分鐘，程度好的同學一場會做 20 題以上。
- 題庫＝這一節各堂課後檢核題（依類型分配）＋新增的換數字題與較難的應用題。範圍是這一節全部內容，加上先備單元。
- 每一題都用 `quizlib.check_item` 核算，用 `ONLY=new- node scripts/quiz-src/preview.mjs raid:<課程 id> <資料夾>` 預覽新增的題目，每張都要看過。
- 規則重點（`shared/raid.ts`）：
  - 只做記憶題，魔王會適應：最近 45 秒全班答對的題目中，普通攻擊超過六成，效果開始變差，最低到 25%。
  - 應用題的大招有合擊加成：每多 1 人 +10%，最多 2 倍。應用題答錯只鎖 3 秒，魔王蓄力只加一半；不會做可以「換一題」，每 30 秒一次，不算答錯。
  - 魔王有 3 種普通攻擊：爪擊、衝撞（要 1 秒防護罩）、連擊（兩下）。25 人以上每 3 秒一次，人少時間隔拉長但最慢 5 秒一次；每下傷害與扣的防護罩跟著頻率調整（每分鐘總量不變）。英雄血量以 2000 為刻度（25 人、8 分鐘）。
  - 魔王有 4 種大招，預告 30 秒，要 3 秒防護罩才能完全擋下：
    - 毀滅衝擊
    - 吸血咆哮（沒擋下的傷害會回到魔王身上）
    - 封印之霧（沒完全擋下，大招計量歸零）
    - 破盾重錘（先打碎一半存量）
  - 英雄血量、魔王血量、魔王攻擊頻率、魔王大招傷害都依人數成比例。
  - 職業被動技能（選角色時顯示）：劍士「堅盾」理解題防護罩多存 0.5 秒；弓箭手「連射」記憶題攻擊 +30%；法師「魔力湧泉」應用題大招計量多 5%。
  - 個人目標：選完角色後設「這一場答對幾題」（依個人最佳建議：追平、+2、+4；沒有紀錄就 3、5、8），可以先不設定。個人最佳記在班級資料（`raidBest`），結算顯示「達成目標」「突破個人紀錄」。
  - 連對保護：連對 2 題以上，第一次答錯不中斷連對（每場一次）。贖回：答錯後下一題做同一類答對，多拿回一半分數。
  - 冒險地圖：老師在魔王戰頁、還沒開戰時，大螢幕顯示這一節三隻魔王，打倒過的打勾並記最快時間（`raidWins`）。
- 測試：`npm run test:e2e` 自己開的伺服器會把資料存到新的暫存資料夾；本機 8787 已有別的開發伺服器時，設 `MCK_PORT=8797` 換連接埠。
- 戰鬥規則與數值在 `shared/raid.ts`（伺服器與各裝置共用）。改數值後用 `node scripts/raid-sim.ts [人數] [秒數]` 模擬，看三種難度的勝率與稱號分布；`STRAT=attack+ultimate` 這類設定可以測極端策略（只做某幾類）。實際開一場：`node scripts/raid-loadtest.mjs [人數] [秒數] [難度]`（只對本機伺服器）。
- 大招 5 種效果（`src/raid-ui.ts` 的 `ULT_SKILLS`、`src/raid-fx.css`），改特效後用 `node scripts/raid-fx-preview.mjs <資料夾>` 截圖逐張看。
- 圖：`public/raid/`（`hero-knight|mage|archer.webp`、`boss-easy|normal|hard.webp`、`arena.webp`，Codex ImageGen 生成）。沒有圖時畫面自動用圖示代替。

## 根式步驟格鬥（運算步驟練習，放在課後檢核頁前面）

- 目的：學生還不熟運算規則時，練「每一步用哪個規則、算出來長什麼樣子」。參考 2026mathgame 的不等式格鬥、直式除法格鬥：紅藍兩隊對戰，每完成一步就出招。
- 一題是一串步驟。每一步分兩小步：
  1. 選規則：4 個選項，例如「根式相乘」「拆出最大的平方因數」「分母有理化」。
  2. 填出下一行：算式裡有空格，學生點數字卡填進去。
- 選對規則、填對算式都會出招。填出最後一行是這一題的最後一擊。答錯扣自己隊伍一點血，但不會直接輸。同一小步連錯兩次會出現提示：發亮的規則，或第一格要填的數字。看過提示才答對的，傷害減半，也不算「一次就對」。
- 分隊與傷害：
  - 開戰時依程度（最近一次測驗或 PK 的答對率）蛇形分成紅、藍兩隊；之後才加入的同學分到人少的一隊。
  - 每一招的傷害除以自己隊伍的人數，人數不同也公平。
  - 先把對方打到 0 就獲勝；時間到時，血多的一隊獲勝。
  - 規則與數值在 `shared/duel.ts`。
- 題庫：`content/duels/<課程 id>.json`，由 `scripts/lessons-src/duel-g8-2-2.mjs` 產生。`npm run lessons` 會驗證題庫，在課後檢核頁前面加一頁「步驟格鬥」；題庫（含答案）另存成 `content/duels.generated.json`，只放在伺服器。
  - 每一題寫成：起始算式、每一步的規則、下一行（含空格）、接受的填法（交換律等）、數字卡（正確的數字＋常見錯誤的數字）。
  - 產生器會算數值核對每一行和原式相等，每一種填法也核對。
  - **範圍**：每一堂只用這一堂（含之前）教過的規則。
- 老師端：開戰前選 5／8／10 分鐘。對戰中與結束後顯示「最需要加強的步驟」：各規則全班的正確率，低的在前。結束後有每個人的傷害、完成題數、一次就對的比例，以及特別稱號（最強攻擊手、終結者、步步精準）。CSV 每一次作答一列。
