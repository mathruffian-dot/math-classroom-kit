## 設計重點

### 作答格式（因式分解不能用 numeric 直接判）

- 3-1 的「留一格 □」會把分解結構給出來（3-1 審核 S1）。十字交乘若寫 `(x+3)(x+□)`，學生用 21÷3 就答完，等於沒在做十字交乘。
- 改用 111 會考第 8 題的問法：**寫成指定形式、填 a**：
  - 二次項係數為 1：`(x+a)(x+b)`，`a<b`，填 a（例題填 a、b）。
  - 隨堂（a≠1）：`(px+a)(qx+b)`，p、q 正整數且 `p<q`，a、b 整數，填 a——不洩漏左欄怎麼拆。
  - 例題、先提公因數、首項為負：給出左欄（`(x+a)(5x+b)`、`2(x+a)(3x+b)`、`-(3x+a)(x+b)`），屬於鷹架。
- `g8-3-2-check.py` 對每一格窮舉所有整數解（p、q 試 1～12，其餘解方程組）、套用條件，**問的那個未知數只能有一個值且等於答案**；有非整數解的題目，程式會檢查題目裡一定寫了「整數」，條件 `a<b`／`p<q` 一定寫在題目裡。這個核算真的抓到一個錯：例 6 原本把 a、b 寫成 −4、2（應為 −2、4），已修正。
- 半完成範例（3-1 審核 R2）：a 堂例 2、b 堂自編題、c 堂例 5 把課本的最後一組十字右下留「?」，學生只填這一格；接著一小題換數字撤除提示；隨堂再完全撤除（`SOLO` 備註要求先紙筆）。留空的那一組從第 0 步就顯示（學生端公布前只看得到第 0 步）。
- 補救練習：任務要求「每個數值題寫 3 輪補救練習」，但 `docs/AUTHORING.md`、`convert-lesson` 技能（2026-10-21 老師回饋）與伺服器（`worker/app.ts` 派補救一律 `retry: true`，派的是答錯的課本原題）都已改成不另寫換數字題庫，3-1 也沒有 `practice`。**這次照目前平台規格沒寫 `content/practice/`**，請老師確認。
- 隨堂只放課本原題（`textbookOnly` 檢查題數），換數字的只出現在半完成範例頁、暖身與左圖示範。

### 3-1 審核問題的預防

- **答案外流**：所有答案都在 `items[].answer`、`correct`、`rubric.reference`；巢狀 items 的遮蔽是平台的（3-1 審核 B1 已由平台修正，本次未改 worker）。逐步講解的圖：學生端只看第 0 步，例題的第 0 步是「不合」的第 ① 組，不含答案。半完成範例留空的那一組是「?」。
- **規準洩漏**：`crit()` 在產生時檢查等級描述不得含數字、x、＝、＋、−、括號等，本題的式子與答案只寫在 `reference`、`graderNotes`。
- **兩個正解**：所有「式子選項」的單選（預測頁、a-pq、b-negx）由 `g8-3-2-check.py` 用 SymPy 判斷「等於原式的選項剛好是 correct」；課後檢核／魔王戰的每一題由 `quizlib.check_item` 核算剛好一個正確。因式分解多種正確寫法（例 6、例 7）只放在「下列哪一個也是正確寫法」的題型，其他題的錯誤選項不放等價寫法。
- **滑桿不保面積**：`algebraTilesAx`、`algebraTiles` 每個滑桿值都是完整的長方形（沒有中間動畫）；十字圖不涉及面積。
- **近重複**：魔王戰檢查「題幹＋選項」完全重複與「題幹」重複（不同題型共用的固定題幹除外）；課後檢核同一份內的同一原式已手動錯開（例如 b 的 q6 改用 x²−2x−15，不和 q10 的 x²−2x−8 重複）。
- **普通攻擊一步完成**：attack 只放「已知一個因式填另一個常數」「交叉相乘的和」「展開的一次項」「先提公因數後填常數」「提出負號的寫法」，完整因式分解一律放 ultimate。
