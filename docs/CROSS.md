- 和其他教師頁一樣要先登入：沒登入打開 `#/games/cross` 或 `#/games` 會回到登入頁（e2e 有測）；學生帳號登入後一律進學生畫面。

- 上方列的「單人大板／雙人對戰」切換到 `#/games/cross-duel`（帶著目前的重點）。

## 畫面與操作

- 上方是題目（KaTeX 排版）；左邊是十字圖，右邊是卡片匣，底下是回饋列與老師按鈕。
- **十字圖四格**：左欄是 x 係數（上 p、下 r），右欄是常數（上 q、下 s）。每一列就是一個因式：(px+q)、(rx+s)。
  - 紫色斜線＝左上 × 右下（p·s），藍色斜線＝左下 × 右上（r·q）。
  - 讀數即時更新：兩個交叉乘積、交叉相乘和與目標（一次項係數）、兩欄各自相乘是否等於 x² 係數與常數項（✓／✗）、目前拼出來的因式。
- **放卡片**：
  - 拖曳（Pointer Events，觸控、滑鼠、觸控筆都可以）：拖到格子放下；拖回卡片匣就收回。
  - 點選：先點卡片（橘色框），再點格子；點已放好的卡片再點卡片匣＝收回；選了卡片再點已放好的卡片＝換位置。鍵盤：Tab 到卡片按 Enter（選取中的卡 `aria-pressed="true"`），再 Tab 到格子按 Enter；格子裡的卡按 Delete（或 Backspace）放回卡片匣，焦點留在那張卡；Esc 取消選取。卡片的讀屏名稱會說出它在哪一格。
  - 放到已經有卡片的格子：兩張交換（從卡片匣來的話，原來那張回卡片匣）。
  - x 係數卡（紫框、斜體 2x）只能放左欄，常數卡（藍框、+3）只能放右欄；放錯欄會提醒，不會放進去。
  - 拖曳中途被打斷一律作廢、卡片留在原位：老師按下一題／換重點／清空／公布答案／提示、選公因數，或系統送出 `pointercancel`、`lostpointercapture`。拖曳中其他手指按卡片不理會。每題的卡片 id 帶題目序號（`q3-c0`），舊題的指標碰不到新題的卡。
  - 每張卡在卡片匣有固定的「家」，拿走後留下虛線框；格子大小固定。放卡片只搬動那張卡的節點、更新讀數，不重畫整個板子，拖曳中 `touch-action: none`，畫面不捲動、不跳動。
- **回饋**（不洩漏答案）：
  - 四格滿且正確：十字圖變綠、「✓ 正確！」並寫出完整的因式分解（「先提公因式」含公因數 k）。
  - 交叉和不對：「✗ 交叉相乘和 = −5，目標 +5，差 10」。
  - 兩欄相乘不對：「✗ 左欄相乘 = 4，要等於 x² 的係數 6」／「✗ 右欄相乘 = 6，要等於常數項 −2」。
  - 顏色之外都有 ✓／✗ 文字。
- **老師按鈕**：
  - 清空：卡片全部回卡片匣，可以重做（同一題重做不再加分）。
  - 提示（漸進）：「先提公因式」的題目還沒選對公因數時先提示「三個係數的最大公因數、負號一起提」；之後第 1 次亮出正確的兩張 x 係數卡（x² 係數為 1 的左欄固定，直接跳到第 2 次），第 2 次亮出正確的兩張常數卡並說明正負，第 3 次四張都亮。提示文字直接寫出發亮的數字（例「2x 和 3x」「−1 和 +2」），不只靠顏色。
  - 公布答案：把正確的卡片放進四格（黃色），要提公因式的題目會一起公布公因數（顯示 原式 = k(…) 那一步）；不加分、連對歸零。
  - 下一題：換一題。同一場、同一個重點從題池依序出題，題池用完前不重複；用完時回饋列提示「「x² 係數為 1」的 N 題都出過了，重新洗牌開始新的一輪」（寫出是哪個重點），換一個種子再來一輪。
  - 上方的重點切換列（和遊戲卡片同樣的四個名稱＋例子）：馬上換成該重點的新題。題目上方的小標籤寫出這一題的重點（混合時每題不同）。
  - 「答對 3 題自動進到下一個重點」：**預設不勾**——選了哪個重點就一直停在那個重點。勾選後，連續答對 3 題（`CROSS_AUTO_STREAK`）按「下一題」會進到下一個重點（x² 係數為 1 → x² 係數不為 1 → 先提公因式）；在「先提公因式」時停用（沒有下一個）；「混合」時整個收起來（不適用）。
- 右上角顯示「答對 n 題・連對 m」。

## 重點（`shared/game-focus.ts`）

老師挑的是這個單元的重點，不是抽象的等級。遊戲卡片、板子的切換列、對戰的開始設定、學生畫面、排行榜、CSV 都用下面的名稱；程式內部仍用產生器的等級 1／2／3。

| id | 名稱 | 一行例子（KaTeX） | 產生器等級 | 題型 |
|---|---|---|---|---|
| `a1` | x² 係數為 1 | x²+5x−14 ＝ (x+7)(x−2) | 1 | 左欄固定是 x、x，只放常數卡 |
| `a-not-1` | x² 係數不為 1 | 6x²+x−2 ＝ (2x−1)(3x+2) | 2 | x² 係數不是 1、正的，三個係數互質 |
| `gcf` | 先提公因式（小字：含首項為負） | 2x²+10x+12 ＝ 2(x+2)(x+3) | 3 | 要先提公因數 k（k ≠ 1，可能是 −1、−2…，首項是負的就一起提），例 −x²+x+6 ＝ −(x−3)(x+2) |
| `mix` | 混合（例子寫「三種隨機出現」） | — | 1、2、3 | 每題由種子決定是哪個重點 |

「先提公因式」的題目一開始十字圖是鎖住的（「先選出公因數」），題目下方是**公因數選項**，學生自己選（2026-11-18b 起，取代老師按的「提出公因數」按鈕）：

- 選項固定是 −5、−4、−3、−2、−1、1、2、3、4、5，每一題都一樣、順序固定，和答案無關（`shared/cross.ts` 的 `CROSS_K_OPTIONS`／`crossKOptions()`）。**全班連線對戰用同一份**（`worker/cross.ts` 的 `CROSS_K_OPTIONS`、`kOptions()` 都從這裡來），兩邊不會不一致。產生器的 k 只會是 2、3、4、5、−1、−2、−3，都在清單裡（單元測試對題池每一題核對）；其他的數是干擾：別的因數、正負號相反、±1。
- 選錯：回饋列顯示「✗ …，再選一次」，選錯的選項標紅框、劃線，可以再選；說明只講選的那個數哪裡不對，不寫出答案（`crossKFeedback`）：
  - 不整除：「3 不是三個係數的公因數」
  - 首項為負卻選正的：「首項是負的，要連負號一起提出」；首項為正卻選負的：「首項是正的，不用提出負號」
  - 是公因數但不是最大的：「2 是公因數，但不是最大公因數」；選 ±1：「提出 1 之後，括號裡的係數還有公因數」
- **選對之前，畫面上只有原式和公因數選項**（大板與雙人對戰都一樣）：卡片匣是空的（「選對公因數之後，數字卡才會出現」），四格一律是 ?x／?、不標「左欄固定」，讀數全是「?」、目標寫「目標 ?」、欄乘積空白、因式寫 (?x ?)。卡片的數字與張數、左欄是否固定、目標、欄乘積都是括號裡的三項式的資訊，看得到就能用「原式係數 ÷ 括號裡的係數」反推 k，所以一律等選對（或公布答案）才畫。e2e 核對：選 k 之前的作答區 HTML（含所有屬性、讀屏文字）除了原式之外，兩題完全一樣（不同的 k、左欄固定與否），也沒有括號裡三項式的 KaTeX 原始碼。
- 選對：顯示 `原式 = k(括號裡的三項式)`，卡片出現、十字圖解鎖，再對括號裡的三項式做十字交乘；目標也是括號裡的一次項係數。括號裡的 x² 係數可能是 1（左欄固定 x、x）或不是 1。
- 鍵盤：Tab 到選項按 Enter／空白鍵；觸控與滑鼠用指標事件（兩個人同時點也各算各的）。選項至少 44×44px（大板 52px 高）。
- 「混合」裡的先提公因式題目走同樣的流程。

- **例子是算過的**：例子不是手寫字串，而是由 `params.sample = {k,p,q,r,s}` 展開（`polyTex(expand(…))`）產生；單元測試核對展開、內部三項式本原、以及用產生器的分類規則 `crossClassify`（k ≠ 1 → 3；x² 係數 1 → 1；其他 → 2）分回自己的重點。同一個測試也對每級 2000 題確認 `crossClassify(crossItem(seed, level)) === level`。
- **對應**：`CROSS_LEVEL_FOCUS`（1 → a1、2 → a-not-1、3 → gcf）、`crossLevelLabel(level)`、`crossFocusFromParams`（網址）、`crossRunFocus(run)`（對戰；8ccf588 存的舊場次沒有 `focus`，照 `level` 對應）、`crossNextFocus`（自動前進的順序）。
- **混合怎麼出題**（`crossMixLevel(種子, 第幾題)`，`shared/cross.ts`）：每 3 題一組，是 1、2、3 的一個排列（由種子決定），所以同一個種子一定同一串、每 3 題三種都會出現。板子用場次種子（`?seed=`），三個等級各自從自己的題池依序抽（題池用完前不重複，規則和單一重點一樣）。板子的種子本來就公開在網址上，所以可以用這個公開函式；**對戰不用 `crossMixLevel`**，改用伺服器的獨立秘密（見〈混合〉列與〈答案保護〉）。

### 之後的單元遊戲怎麼加重點

1. 在 `shared/game-focus.ts` 的 `GAME_FOCUS` 加一組：`遊戲 id → [{ id, label, example?（LaTeX）, exampleText?, note?, params }]`。`params` 由那個遊戲的產生器自己定義（十字交乘是 `{ levels, sample }`）。id 用小寫英數與連字號，會出現在網址與儲存的資料裡，定了就不要改。
2. 例子盡量由產生器的參數算出來（像 `sample`），並寫單元測試用產生器的分類規則核對它屬於那個重點。
3. 畫面用 `focusOptionHtml(f)`（`src/cross-board.ts`：名稱＋KaTeX 例子＋小字說明）畫選項；伺服器用 `isXxxFocus` 這類函式嚴格驗證 id（不認得的回 400）。
4. 已經存下來的舊資料若只有數字等級，要寫一個像 `crossRunFocus` 的對應函式，並加一個舊資料形狀的單元測試。

## 出題規則（`shared/cross.ts`）

- 題目：`ax²+bx+c = k(px+q)(rx+s)`，全部整數。`inner = (a,b,c)/k` 是本原三項式（`gcd = 1`、首項為正）。
- **符號規則**：左欄 p、r 一律是正數（x 係數卡只有正數），正負號全部放在常數；整個式子的負號由 k 提出。所以 (−2x+1)(−3x−2) 這種寫法不出現，要寫成 (2x−1)(3x+2)。
- 判定 `crossJudge(item, fill)`：接受任何數學上成立的填法（p·r = a'、q·s = c'、p·s + r·q = b'，p、r > 0），回傳 `{ ok, complete, products: [p·s, r·q], sum, target, diff, leadProduct, constProduct, leadOk, constOk, reason }`。第二階段伺服器端也用，所以對任何輸入都嚴格：
  - 空格是 `undefined`／`null`。左欄固定（`leadLocked`）時左欄可以省略、填 `null` 或 `1`；明確填了別的數就判錯（例：x²+5x−14 填 2、3、7、−2）。原因看 `item` 有沒有帶 `cards`：沒帶 `cards` → `reason: 'lead'`；帶了 `cards`（板子上的完整題目）→ 左欄固定時沒有 x 係數卡，填的數不是卡片，`'card'` 優先，回傳 `reason: 'card'`。
  - 不是安全整數（小數、NaN、字串…）→ `reason: 'invalid'`。
  - `item` 帶 `cards` 時，每個數字都要是該欄種類的卡，同一張卡不能用兩次 → 否則 `reason: 'card'`。內部三項式本原，因此成立的填法只有標準答案和「上下兩列對調」——單元測試把每題所有卡片擺法都列舉驗證過。
- 以下的「等級 1／2／3」是產生器內部的等級（＝ a1／a-not-1／gcf）。
- 範圍（一律作用在**原式**的係數，等級 3 也是）：|a| ≤ 12、|b| ≤ 30、|c| ≤ 60。等級 3 提出 k 之後，括號裡的限制是 a′ ≤ ⌊12/|k|⌋、|b′| ≤ ⌊30/|k|⌋、|c′| ≤ ⌊60/|k|⌋。等級 1 的常數 |q|、|s| ≤ 12，等級 2 ≤ 9；x 係數拆法 p ≤ 6。單元測試對每級 3000 題斷言 |a| ≤ 12、|b| ≤ 30、|c| ≤ 60。
- 不出：b = 0、c = 0、完全平方、兩個常數相同（q = s，卡片會重複）。
- 可重現：`crossItem(seed, level)` 用 mulberry32；`crossSeed(場次種子, 等級, 第幾題)` 算每題的 seed；`crossSequence(場次種子, 等級, 題數)` 依序產生且同一場不重複。第二階段可以給每位學生不同的種子。
- 題池：`crossPool(場次種子, 等級, 大小)` 依 `crossSeed(…, 0, 1, 2…)` 收集不重複的題目，第一題就是 seed 0 那題。大小 `CROSS_POOL_SIZE`：等級 1 200（範圍內全部的題目，單元測試列舉核對）、等級 2 150、等級 3 150。板子從題池依序抽題，用完才開新一輪（第 2 輪起用 `crossSeed(場次種子, 等級, 1000000+輪次)` 當種子，第一題避開上一題）。

## 卡片與干擾卡

- 左欄固定（x² 係數 1）：6 張常數卡＝正解 2 張＋干擾 4 張。
- 要放 x 係數卡：8 張＝x 係數正解 2 張＋干擾 1–2 張，常數正解 2 張＋干擾 2–3 張。
- 常數干擾卡的順序：
  1. **正負號放反**：−q、−s（一定有一種擺法兩欄乘積都對、交叉和剛好是 −b；q = −s 時對調兩張常數就是這個陷阱）。
  2. **常數的其他拆法**：例如 −14 的 14、−1、1、−7、2…（小的優先）。
  3. 不夠時補相近的數（q±1、2q…）。
- x 係數干擾卡：a' 的其他拆法（6 → 1、6）；a' 是質數時補一張拆不出來的數。
- 干擾卡彼此不同、也不和正解同數字；x 係數卡全是正數。

每位同學在 iPad 上各自一題（數字都不一樣），伺服器出題、伺服器判定；老師大螢幕看排行榜，可以開紅藍兩隊拔河。程式：`worker/cross.ts`（伺服器）、`src/cross-live.ts`＋`src/cross-live.css`（畫面），課堂裡的入口在 `src/main.ts`、`worker/app.ts`。

### 怎麼開始

1. 老師照平常「開始上課」（任何一課都可以），學生用平常的學生入口（班級代碼＋座號）登入課堂，不用另外登入。
2. 開對戰（兩種入口，效果一樣）：
   - 課堂畫面右側老師工具列（抽籤、搶答旁邊）按「**十字交乘對戰**」→ 選**重點**（四個選項，各有名稱＋一行例子）、「答對 3 題自動進到下一個重點」（預設不勾；和大板一樣，選「先提公因式」時取消勾選並停用、選「混合」時隱藏）、限時（預設不限時）、「紅藍兩隊拔河」與勝負門檻 → 「開始對戰」。
   - 側欄「遊戲」→「十字交乘（全班連線對戰）」卡片 → 選上課中的課堂、重點（同樣的四個選項＋自動前進的勾選）、要不要拔河 → 「開始對戰」，會直接跳到那一堂的老師畫面。
3. 學生端自動切到作答區、自動拿第一題；對戰中教材先收起來，作答卡佔滿 iPad 畫面（直向、橫向都不用捲動）。
4. 進行中的控制區：暫停／繼續、開啟／關閉紅藍拔河、重新開始（新的一場，分數歸零，設定與分隊保留，上一場紀錄留著）、結束這一場；結束後可以「重新開始」或「關閉」。開別的活動（測驗、PK、魔王戰、步驟格鬥）或結束課堂會一併結束對戰。

### 學生 iPad

- 原式（KaTeX）、十字圖四格、卡片匣、送出。點卡片 → 點格子；點已放的格子把卡收回。x 係數卡只能放左欄、常數卡只能放右欄（放錯會提醒，不會送出）。左欄固定（x² 係數 1）時左欄直接顯示 x、x。
- 「先提公因式」的題目先在「先提出公因數」選 k，選了才解鎖十字圖。選項**每一題都一樣**：固定的 −5、−4、−3、−2、−1、1、2、3、4、5（順序固定，`CROSS_K_OPTIONS`，和大板、雙人大屏對戰共用 `shared/cross.ts` 的同一份），和正確答案無關，學生必須自己從原式算出公因數（k 只會是 2、3、4、5、−1、−2、−3）。單元測試確認 3000 題的選項完全相同，「找互為正負的一對」「挑絕對值最大」「固定位置」這類只看選項的猜法都不會比亂猜同一個數好。
- 卡片：正解（左欄固定時 2 張常數卡，否則 x 係數 2 張＋常數 2 張）＋2 張干擾卡：左欄固定時是 2 張常數干擾卡（優先正負號放反），共 4 張；要放 x 係數卡時是常數 1 張（優先正負號放反）＋x 係數 1 張，共 6 張。所以 x² 係數為 1：4 張、不為 1：6 張、先提公因式：4 或 6 張。卡片順序由伺服器打亂並重新編號（`k0`、`k1`…），看不出哪張是正解。
- 送出（先顯示再同步）：按下就把放好的格子標成中性的灰色「已送出／判定中」，鎖住所有操作；**不在本機猜對錯**。伺服器回來才換成 ✓（綠）／✗（紅），並顯示得分明細、交叉相乘和與因式分解。網路失敗或被拒：拿掉判定中、解鎖，卡片留著可以再送。
- 晚到的回應（`src/cross-live.ts`）：本機狀態以「範圍」＝路由（`routeVersion`）＋課堂＋場次管理，範圍一變（換頁、換課、老師重新開始）就整個重設：`revision` 歸零、拿題中旗標清掉、判定中清掉、世代（`gen`）加一。每個拿題／送出請求都記下世代：
  - 世代不同（換頁、換課、換場）的回應一律丟掉；舊請求的 `finally` 只清自己那一次的旗標，不影響新世代。
  - 拿題回應：revision 比本機已知的舊（推送已經更新過），或題目是自己已經送出、拿到判定的（`done`），就不裝回去，也不清掉目前的判定。
  - 送出回應：要是同一個判定中、同一題（`itemId`）才顯示判定；分數、連對、答對／作答數用回應裡伺服器算好的 `mine` **直接指派**（推送先到也不會重複累加）。回應比已知的 revision 舊時，統計以較新的推送為準。
  - 推送：比本機已知 revision 新就照推送；舊的或一樣的推送，自己的題目與分數以本機為準；已經送出的題目不會被推送裝回去。
- 冷卻：答錯後「下一題」按鈕變成灰色的「下一題（N 秒）」倒數，時間到才能按（不是錯誤訊息）。重新整理後一樣（冷卻時間在學生畫面的 `mine.cool`）。
- 不跳動：同學得分的推送只更新分數、連對、等級、名次、拔河、時間這幾個小元素；只有換題、送出／判定、暫停、結束時才重畫作答卡（`crossCardKey`）。自己的點選只換十字圖與卡片匣（尺寸固定），題目不動。
- 答完按「下一題」才拿下一題（速度從拿到題目開始算，看結果的時間不算）。

### 計分與升級（`worker/cross.ts`）

| 項目 | 規則 |

| 基本分 | 答對才有：x² 係數為 1：100、x² 係數不為 1：130、先提公因式：160 |
| 速度 | 伺服器量「發題 → 送出」的時間：10 秒內 +50，之後線性遞減，40 秒以上 +0（暫停的時間不算） |
| 連對 | 這題之前已經連對 n 題：+10n，最多 +50 |
| 答錯 | 0 分、連對歸零，**不扣分**；但要冷卻（見下） |
| 快得不合理 | 發題到送出 x² 係數為 1 不到 2 秒、不為 1 不到 3 秒、先提公因式不到 4 秒：答對照算基本分與連對分，**沒有速度分** |
| 前進 | **預設固定在老師選的重點**。勾了「答對 3 題自動進到下一個重點」才在同一個重點連對 3 題後前進（x² 係數為 1 → x² 係數不為 1 → 先提公因式）；「混合」不前進 |
| 混合 | 每位同學每一題由伺服器決定是哪個重點：`crossMixOrder(混合秘密, 場次, 座號, 第幾組)`（`worker/cross.ts`；`seat.m` 計數，每 3 題一組），SHA-256(混合秘密 ‖ 場次 ‖ 座號 ‖ 組號) 選 6 種排列之一，每 3 題三種各一、順序每人不同；基本分、速度門檻照**這一題實際的重點**算 |

### 紅藍拔河

- 開始時勾「紅藍兩隊拔河」：上線的同學依程度蛇形分隊（和步驟格鬥同一套 `duelTeams`），晚到的分到人少的一隊；開戰後才開啟拔河時，已經在玩的和上線的同學一起分隊。
- 兩隊用**平均分**比（人數不同也公平）。繩結位置 =（藍隊平均 − 紅隊平均）÷ 門檻，往領先的一隊移動（CSS transform 動畫，版面不動）。學生端也有小拔河條，看得到兩隊總分，看不到排行。
- 勝負（`crossMarginWinner`、`crossLeader`，三種結束方式規則一致）：
  - 提前獲勝：**兩隊都有人**、平均分差 ≥ 門檻（預設 300，可選 200／300／500／800）。有一隊沒人時不會提前結束。
  - 時間到、老師按結束：兩隊都有人 → 平均分高的獲勝，一樣是平手；只有一隊有人 → 那一隊平均分 > 0 才獲勝，否則平手；兩隊都沒人 → 平手。**沒有人的隊伍永遠不會獲勝。**

### 老師大螢幕

- 參加人數、全班答對／作答與答對率；排行榜前 10 名（座號、隊伍、目前的重點、答對／作答、連對、分數；列數固定，不會跳動）；最近送出的 8 題（只有原式與對錯）。
- 「公布」：按某一題旁邊的「公布」，用**題目 ID**（不會變；不用會位移的陣列索引）向伺服器要那一題的因式分解，只顯示在老師畫面。前端的公布快取以「場次＋題目 ID」為鍵，重新開始或紀錄變多都不會顯示到別題。
- 送出紀錄（`crossPlay[場次].log`）：每一次送出一筆（題目 ID、座號、這位同學的第幾題、等級、對錯、得分、秒數、時間）。**容量政策**：每一場最多 2400 筆（約 40 人 × 每人 60 題，`CROSS_LOG_CAP`），超過時丟掉最舊的並記下丟了幾筆（`dropped`），CSV 會多一列說明。另外每位同學的 `past` 只留最近 30 題，只用來出題時避開重複。這和步驟格鬥的作法一致（逐筆紀錄跟著課堂存，畫面上只顯示最後幾筆）。
- **整堂課的容量政策**（`crossPrune`，每次開始／重新開始一場時執行）：只有最近 3 場（`CROSS_KEEP_ROUNDS`）保留逐題紀錄與每人最近 30 題；更早的場次**封存**成每人總計（分數、答對、作答、最高連對、等級；`archived: true`，逐題紀錄筆數併入 `dropped`）；最多保留 30 場（`CROSS_MAX_RUNS`），再早的連場次紀錄一起刪除。所以不論重開幾場，十字交乘佔用的容量都有固定上限（約 3 場 × 每場數百 KB ＋ 30 場的總計），離課堂 8 MiB 上限很遠，送出與結算都存得進去。封存的場次在 CSV 是一列說明加每人一列總計（原式欄寫「（總計）」、對錯欄寫「答對/作答」），JSON 的 `crossLog` 帶 `archived` 與 `totals`。
- CSV 匯出（課堂匯出）每一次送出一列（來自送出紀錄，不是最近 30 題）：類型「十字交乘對戰」、座號、重點名稱（例「x² 係數不為 1」，不寫 L 數字）、這位同學的第幾題、原式、對錯、得分、隊伍與秒數。課堂匯出 JSON 另有 `crossLog`（每一場的紀錄，含原式與因式分解，不含種子；每筆有數字的 `level` 與老師看得懂的 `focus`／`focusLabel`）；`crossRuns` 的新場次帶 `focus`。匯出只有老師能用。

### 安全模型

- 答案只在伺服器：`StoredSession.crossPlay[場次].seats[座號]` 存秘密種子、目前題目的種子、發出去的卡片、送出過的題目。`session.cross`（學生看得到）只有設定、分隊、時間與勝負。
- 學生收到的題目只有：題目 id（隨機）、等級、原式係數、左欄是否固定、卡片（id、種類、數字）、「先提公因式」的公因數選項。沒有因式分解、沒有哪張卡放哪格、沒有標出干擾卡。因式分解只在**自己送出之後**的回應裡出現。老師畫面是彙總；因式分解要按「公布」才拿。
- 每位同學每一題的種子 = `crossSeed(場次秘密 ^ 座號雜湊, 等級, 第幾題)`（和 8ccf588 相同，舊場次照用）；發題時避開同學目前的題目與自己最近 30 題，所以同一時間每個人的題目都不同。
- 混合的出題順序用**另一個秘密** `crossPlay[場次].mixKey`（開場時 `crypto.getRandomValues` 產生 32 bytes，只在伺服器，不進任何畫面、推送、公布或匯出；單元測試檢查過）。順序 = SHA-256(`mixKey` ‖ 場次 ID ‖ 座號 ‖ 組號) 的前 4 bytes 選排列（`worker/sha256.ts` 同步版，單元測試和 `node:crypto` 核對）。出題種子 `secret` 完全不參與排序：學生看得到每題的重點，但從順序推不回 `secret`、也推不回題目。8ccf588 存的場次沒有 `mixKey`，第一次用到混合時才補（非混合的舊場次永遠不需要）。
- 開始對戰（`cross-start`）的欄位，**只要有送就先驗證型別**（不對一律 400）：`focus` 只接受 `a1`／`a-not-1`／`gcf`／`mix`；`escalate`、`lock` 必須是 true／false；`level` 必須是 1～3 的整數。語意：
  - **新格式**（有 `focus` 或 `escalate`，或什麼都沒送）：重點 = `focus`（沒送 `focus` 時用 `level` 對應，再沒有就是 `a1`）；要不要前進**只看 `escalate`**（沒送 = 不前進），`lock` 不採用；`gcf`（沒有下一個重點）與 `mix` 一律不前進。例：`{level:2, escalate:false}` → 「x² 係數不為 1」、不前進；`{focus:'a1', lock:false}` → 不前進。
  - **舊格式**（只有 `level`／`lock`，8ccf588 的畫面）：對應到同一級的重點，沒勾鎖定就照舊自動前進。
  - 場次存 `focus`、`level`（重點的等級；混合是 1）、`lock`（＝不前進）。8ccf588 存的場次沒有 `focus`，讀取時用 `crossRunFocus` 照 `level` 對應。單元測試用**真正的 8ccf588 伺服器**（從 git 取出打包）跑出作答中的場次（已升級的同學、手上的題目與卡片、送出過的題目、冷卻、每分鐘送出紀錄），換成新版後原題不變、原題送出有效、重送被拒、分數與後續升級照舊、冷卻照樣擋。
- 送出驗證：`itemId` 必須是目前這一題（送出後就清掉，重送同一題 → 409）；`cards` 只能有四格的鍵，每格是這一題發出去的卡片 id，同一張不能用兩次、種類要對欄，左欄固定時左欄不能放卡；「先提公因式」的 k 必須是選項之一。格式錯 → 400，不算一次作答。判定用 `crossJudge`（接受上下兩列對調等所有成立的填法）。
- 限速與防亂猜：見〈計分與升級〉的表。暫停中、結束後、舊場次的 `runId` 都拒絕（409）。只有學生能拿題、送出；只有老師能公布；所有 `cross-*` 控制與 JSON／CSV 匯出都要老師身分（學生 403，單元測試逐一檢查）。
- 重複拿題（`next`）是冪等的：已經有題目就原題奉還，**不加 revision、不保存、不推送**（回應帶 `X-Classroom-Quiet`，`worker/index.ts` 看到就不廣播）；只有第一次分隊或出席時間超過 30 秒沒更新時才寫入。
- 限時到期（伺服器結算）：開始、繼續、重新開始時，`worker/app.ts` 在**保存課堂之前**呼叫 `ctx.scheduleCross` 記下這一堂的到期時間（Durable Object storage 的 `cross-due`，同一堂取較早的時間），並把 alarm 排在最早的到期時間（不會把較早的 alarm 改晚）。
  - **排程跟著已保存的資料走**：暫停、結束、收起時不會馬上從 `cross-due` 移除；alarm 叫醒時讀「已保存」的課堂確認——還沒到期的照實際到期時間重排，已暫停／已結束／已收起的才移除，到期的結算並**保存成功之後**才移除（保存失敗就整份排程原封不動，5 秒後再試）。所以「先改排程、後保存失敗」不會失去叫醒；多叫醒一次只是讀一下、沒有變更。
  - **不被回家作業批改拖住**：Durable Object 只有一個 alarm，和回家作業背景批改共用。`alarm()` 一叫醒就先結算到期的對戰，然後才開始批改；批改（單次 AI 呼叫最長 150 秒）進行中，每秒（或到期時間一到）再檢查一次對戰，到期就在佇列內結算（`settleCrossSession`：記下結束時間與勝負、更新 `crossRuns`、revision 加一、保存、推送），也接得住批改期間才開始的限時對戰。批改照原本的租約與提交防護，一份作業只批一次。最後把下一次叫醒排在兩者較早的時間。全班閒置也會準時結束。
  - **畫面函式唯讀**：`crossView()` 不改任何資料；時間到了但還沒結算時，畫面先顯示結束（`endedAt＝deadline`），真正的結束只走結算（alarm、`op: 'settle'`、到期後的拿題／送出、老師的控制指令先結算），一定會更新 `crossRuns`、revision 並推送。
  - 保險：用戶端發現時間到了但還沒收到結束時送 `op: 'settle'`（老師 0.3 秒後、學生多等 0.8–2.8 秒錯開），伺服器在佇列內結算，可以重複呼叫（已結束就只回目前狀態、不推送）。時間到之後才到的拿題／送出也會先結算、保存，再回 409（帶 `X-Classroom-Changed` 讓全班收到推送）。
- 單元測試把學生收到的每個 HTTP 回應與即時推送（`liveView`）都檢查過：送出前不含 `factored`、種子、`crossPlay`，也不含兩種順序的因式分解字串；e2e 對瀏覽器實際收到的回應與 WebSocket 訊息做同樣的檢查。

### 已知限制

## 雙人大屏對戰（2026-11-18b）

老師的大觸控螢幕上，兩位同學同時上台，左右各一題，時間內答對題數多的獲勝。純前端（不連伺服器、不記名、不存紀錄）。程式：`src/cross-duel.ts`（畫面）、`src/cross-pad.ts`（每一邊的作答區，和大板同一個元件）、`shared/cross-duel.ts`（出題配對、勝負、計時，純邏輯）。

### 怎麼打開

- 「遊戲」頁第三張卡片（順序：大板操作、全班連線對戰、雙人大屏對戰）「十字交乘（雙人大屏對戰）」：先選時間（1／2／3 分鐘，預設 2 分鐘），再按重點（四個選項，名稱＋例子）。
- 大板上方列的「單人大板／雙人對戰」切換（帶著目前的重點）；對戰頁上方列也有同樣的切換，開始設定畫面有「返回遊戲活動」「改用單人大板」。
- 網址：`#/games/cross-duel?focus=a1|a-not-1|gcf|mix&time=60|120|180&seed=123`
  - `focus` 預設 `a1`（不認得也是 a1）；`time` 只接受 60／120／180，其他一律 2 分鐘；`seed` 固定題目（示範、測試），沒有時隨機。
  - 測試用：`&test=1` 時 `time` 可以是 1～600 的任何整數秒（e2e 用 6 秒驗證時間到），而且頁面有 `window.__crossDuelTest`（`skew(ms)` 把時鐘往前撥、`hold(tick, advance)` 暫停計時器的拍子與自動換題、`remaining()`、`settled()`），e2e 用來重現截止前／後的最後一個輸入與延遲的拍子。hook 只屬於用 `test=1` 打開的那一個畫面：這個畫面存續期間網址一直保留 `test=1`（在開始設定改選正式的 1／2／3 分鐘也一樣）；換頁（`hashchange`）或畫面不在頁面上就撤掉 `window.__crossDuelTest`，新的對戰畫面一打開也先撤掉舊的，而且留著的舊參照呼叫起來什麼都不做（每個操作先確認建立它的畫面還在）；hook 改的時鐘偏移、暫停拍子都是那個畫面自己的變數。所以不帶 `test=1` 的一般對局沒有 hook、也不會被任何 hook 影響（e2e 有測）。
  - 按「開始」後網址改寫成實際的 `focus`、`time`、`seed`（再來一局換新的 seed）。
- 和其他教師頁一樣要先登入（沒登入回登入頁，e2e 有測）。

### 流程

1. 開始設定：重點（四個）、時間（1／2／3 分鐘）、「開始」。
2. 倒數 3-2-1（作答區看得到但鎖住），然後開始計時。
3. 對戰：左方（紅）、右方（藍）各有自己的題目、十字圖四格、卡片匣、即時的交叉乘積與和、「答對 n 題」；先提公因式有自己的公因數選項。上方是大計時器（剩 10 秒變紅）、暫停／結束。
   - 答對（四格都對；先提公因式還要先選對 k）：十字圖變綠、寫出因式分解，那一邊 +1，約 0.8 秒（`CROSS_DUEL_ADVANCE_MS`）後換那一邊的下一題；另一邊完全不動。
   - 答錯：和大板同樣的訊息（交叉相乘和差多少、哪一欄相乘不對），直接移動卡片再試。
   - 沒有提示、公布答案、跳過；老師可以「暫停」（兩邊鎖住、時間停止，暫停的時間不算）或「結束」（立刻結算）。
4. 時間到：兩邊鎖住，結果畫面寫出「左方（紅）獲勝！3 比 2」或「平手！2 比 2」與兩邊題數；「再來一局」（同樣的設定、新的 seed，直接倒數）、「回選單」（回開始設定）。

### 截止時間（時間到）

- 以實際時間（`performance.now()`）為準，不靠計時器的拍子：**每一個作答輸入**（按下卡片／格子／公因數、放卡、退卡、選 k；`createCrossPad` 的 `guard`）與**計分**之前都核對；已經過了截止就不接受這個輸入、立刻鎖住兩邊並結算。所以「拍子還沒來、最後一張卡在截止後才放」不會加分。
- 每 0.1 秒的拍子只負責更新時鐘、沒有人操作時結算；分頁切到背景時拍子會被瀏覽器節流，所以 `visibilitychange`、視窗 `focus`、`pageshow` 時也立刻核對。過了截止才按暫停＝直接結算。自動換題（0.8 秒）也先核對。
- 結算只做一次（`data-settled` 永遠是 1；再來一局重新計）：之後的輸入、延遲到的拍子、焦點事件都不會再結算或改分數。

### 公平出題（`shared/cross-duel.ts`）

- `crossDuelDeck(seed, focus)`：每個等級一個佇列，從題池（`crossPool`，種子 `crossSeed(seed, 等級, 3000000 + 輪次)`）依序取還沒出過的題，**配對**取出：左邊取佇列的第一題 a，右邊取佇列裡下一個和 a **題型一樣**的題（`crossDuelShape`：等級＋左欄是否固定＋k 是正、負或 1）。
- **嚴格按題型分桶**：佇列裡找不到同題型的另一題（題池尾端剩下別的題型）就再拿下一輪題池，直到找到為止；絕不拿別的題型補。單元測試：4 種重點 × 40 個 seed × 5 種題池大小（含 2、3 題的極小題池）× 40 對，每一對題型、卡片張數都一樣。
- 所以第 i 題兩邊同一個重點（混合用 `crossMixLevel(seed, i)`，兩邊同一串，每 3 題三種各一）、卡片張數一樣、步驟一樣，數字不同。
- **整局不重複**：左右兩邊合起來，每一題整局只出一次（換題池的輪次時也只加沒出過的題），所以同一邊不重複、兩邊的題目集合不相交——不管誰答得快，同一時間兩邊都不會是同一題。單元測試：每邊 90 題；極小題池（2～7 題，一直換輪）每局 120 題都不重複。
- **題目用完（耗盡）**：連續幾輪題池都拿不到新題＝這個重點的題目整局都出過了（x² 係數為 1 一共 200 題＝每邊 100 題，正常一局到不了；另外兩個重點的題更多）。這時**不重新洗牌、停止發題**：從那一對起 `deck.pair(i)`／`deck.item(side, i)` 一律是 `null`（`deck.exhausted(i)`），之後每一對都是 `null`（混合時任何一種用完就整串停止）；配不到同題型搭檔的題直接丟掉、不出。畫面上那一邊答完最後一題後鎖住（留著上一題的綠色答案），回饋列顯示「這個重點的題目都出過了，這一邊不再出新題。」；另一邊照常作答到同一個位置也一樣停止。所以「整局不重複」「兩邊不會同時同一題」是程式保證，沒有例外——包括一邊已經用完、另一邊還停在很早的舊題（單元測試）。
- 第 i 對只由 seed 決定（依序算好，和哪一邊先要題無關），同一個 seed 一定同一串（在同一對用完）。
- 種子在網址上（老師的畫面），不是秘密；這是課堂比賽，不是線上對戰。

### 多點觸控

- 每一邊是一個 `createCrossPad` 實例，指標事件只掛在自己的容器上；拖曳以 `pointerId` 追蹤、卡片 `setPointerCapture`，所以手指滑到另一半，事件還是回到原來那一邊。
- 放下目標（`elementFromPoint`）只認自己容器裡的格子或卡片匣：從左邊拖到右邊的格子放開＝沒放進去，卡片留在原位。
- 每一邊同時只有一個拖曳；同一邊的第二根手指按卡片不理會（不搶走拖曳、也不變成選取），另一邊照常可以拖。點選（先點卡片再點格子）每一邊各自記，左邊選了一張不影響右邊。
- `pointercancel`、`lostpointercapture` 只取消那一根手指（那一邊）：進行中的拖曳作廢，**還沒完成的點選（格子、卡片匣、公因數選項）也作廢**，之後同一個 pointerId 的 pointerup 不做任何事；暫停、結束、換題也會取消那一邊進行中的拖曳。
- 對戰畫面整個 `touch-action: none`、`overscroll-behavior: none`、不能選字；長按選單與 Safari 的兩指縮放手勢（`gesturestart`）都擋掉。
- 一邊放卡片、答對換題，只更新那一邊的節點；計時器每 0.1 秒只改那一個文字。
