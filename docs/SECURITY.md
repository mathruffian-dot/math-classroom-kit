# 隱私與安全界線

這是一套可自行部署的教學框架。學生仍以帳號對應作答，因此「匿名顯示統計」**不是**無法追溯身分的真正匿名問卷。教師可以讀取自己班級的個別作答。

## 身分與資料

- 正式教師身分由 Supabase Auth 驗證，再檢查 Worker 的教師電子郵件允許名單。
- 正式學生以班級＋座號＋隨機識別碼登入；識別碼交給該學生，不能列在公開投影、教材或 GitHub。
- 每個班級可在「班級」頁開關「學生登入需要個人識別碼」，**預設停用（測試階段）**：停用時只要班級代碼＋座號，知道班級代碼的人都能冒用任一座號，正式上課前請開啟。開啟時會撤銷該班沒用識別碼的既有登入。
- 正式學生識別碼使用隨機 10 字元，伺服器保存 HMAC-SHA256 驗證值，不保存明文。重發識別碼會撤銷舊登入。
- Supabase secret／service-role key 與 AI key 僅置於 Worker Secrets。前端不直接讀取正式資料表。
- 學生只能存取自己班級的有效場次與自己的答案。教師可管理的資料也受擁有者檢查。
- 標準答案與教師備註必須由伺服器過濾；前端隱藏按鈕不是權限控制。
- 記錄僅用於授課與形成性回饋。需要學生姓名或跨校分析時，先另行設計資料最小化與權限。

## AI 資料流

只有教師可以呼叫分析。未設定金鑰時使用明確標示的模擬結果。傳送回答摘要前排除班級、座號、識別碼與內部使用者 ID；敏感題不送出，且必須允許該題 AI 分析。

即使移除身分欄位，學生仍可能在自由文字自行填入可識別資訊。正式使用前由教師告知用途與限制，選擇符合學校要求的供應商、模型與資料處理設定。每日次數限制只限制呼叫量，不能保證實際費用；另在供應商後台設定預算。

AI 次數按每位教師的 UTC 日期保存，失敗的呼叫也計入；預設每天 20 次，可由部署者調整。這個限制與模型 token 單價、供應商帳單或全站月預算不是同一件事。

AI 輸出不直接寫回學生答案，批改結果需教師覆核後才發回，不取代教師判斷。自訂 HTML 不可持有金鑰或直接發出 AI 請求。

## 公開發布前

公開 GitHub 僅包含程式、規格、虛構示範與可散布的素材。排除：

- `.dev.vars`、`.env`、token、cookie、私密 key 及服務密碼。
- 真實學生名冊、識別碼、答案、教師備份及私人連結。
- 未授權教材 PDF、圖片、影片與媒體附件。
- 含個人資料的 log、Playwright trace、截圖及瀏覽器狀態。

`.gitignore` 只是減少誤傳，不能撤回已提交過的秘密。若秘密外洩，先撤銷／輪替金鑰，再處理 Git 歷史及產物。

## 正式使用前仍需驗證

對自己的部署測試跨班／跨教師存取、登出、過期登入、未揭露答案、同時提交、備份還原與 AI 故障。不要把本機模擬或原始碼檢查宣稱為雲端安全稽核。v0.1 snapshot 儲存適合小型框架驗證；大量部署前需要重新評估資料模型、負載、備份與監控。

若回報問題，公開 issue 只放去識別的重現方式。涉及可利用的漏洞時，使用 GitHub repository 的私人漏洞回報管道（若已啟用）或其他私人維護者管道，勿公開真實憑證或學生資料。
